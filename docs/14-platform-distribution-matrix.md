# 飞书 / 企业微信 / 钉钉分发与接入资质矩阵

核验日期：2026-11-08

本文只回答“怎样让普通用户最快接入”，以及每个平台需要什么主体资质、审核和部署条件。结论以平台官方文档为准；正式提审前仍需用企业主体在开发者后台逐项确认，因为平台会调整类目、权限和审核规则。

## 结论

普通用户不应被要求创建企业自建应用。真正可复制的大众路径是：

1. 你们完成服务商/ISV 入驻。
2. 上架一个支持多租户的官方应用或机器人。
3. 用户在平台应用市场、安装链接或企业管理员授权页完成安装。
4. 用户扫码或点击进入机器人，发送桌面端生成的 pairing code。
5. MiHome Mac 主动连接你们的云端控制面，家庭设备仍只在本机执行。

当前仓库只实现“企业自建应用 / 本机直连”路径。它适合内部验证和企业极客试用，不足以直接支撑公开市场上的普通用户分发。

## 当前代码验收边界

- 接入中心已提供官方文档入口、凭据字段说明、长连接/Webhook 模式选择、连接测试、完整本机回调地址复制和常见错误诊断。
- 飞书已实现单聊首次进入与机器人进群后的自动欢迎，并要求使用官方事件和机器人消息权限。
- 飞书自建应用已使用真实租户完成凭据、长连接、文本消息、状态查询、自动重连和语音资源下载转写链路联调；首次欢迎事件仍需在真实租户中单独验证。
- 企业微信和钉钉目前仅完成本机自动化测试，尚未在真实租户中完成发布、权限与网络环境联调；真实平台验收仍是公开分发前的必做项。

## 路径矩阵

| 平台 | 当前可用路径 | 适合谁 | 用户侧动作 | 你们需要的资质 | 审核与发布 | 是否需要公网回调 | 当前仓库支持 |
|---|---|---|---|---|---|---|---|
| 飞书 | 企业自建应用 + 事件长连接 | 单家企业内测 | 管理员创建应用、配置权限、发布、添加机器人 | 企业管理员权限 | 企业管理员审核自建应用，配置可用范围 | 否，长连接模式不需要 | 已支持 |
| 飞书 | 商店应用（ISV） | 面向多个飞书租户公开发行 | 从应用中心安装，或通过链接安装 | ISV 入驻、企业主体、隐私与安全材料 | 服务商入驻、方案/资质审核、安全审核、商店发布审核 | 通常需要云端服务；长连接可作为事件通道，但不能替代多租户控制面 | 未支持云端多租户 |
| 企业微信 | 企业智能机器人 API 长连接 | 单家企业内测 | 企业管理员创建智能机器人并授权 | 企业管理员权限 | 企业侧创建、配置、启用 | 否 | 已支持 |
| 企业微信 | 第三方应用 / 服务商应用 | 面向多个企业客户 | 企业管理员从应用市场安装并授权 | 服务商入驻、企业主体、应用材料 | 服务商后台创建应用、提交上线/审核；进入推荐位还有额外运营要求 | 取决于应用能力，通常需要云端回调 | 未支持第三方授权与云端多租户 |
| 钉钉 | 企业内部应用 + 机器人 Stream | 单家企业内测 | 管理员创建应用、添加机器人、发布并设置可用范围 | 企业管理员权限 | 企业内部应用发布，管理员设置可用范围 | 否 | 已支持 |
| 钉钉 | 第三方企业应用（ISV） | 面向多个钉钉组织 | 管理员从应用市场安装并授权 | 产品方案商/ISV 入驻、企业主体、部署与安全材料 | 创建 ISV 应用、提交上架、平台审核、类目运营审核 | 通常需要云端服务 | 未支持第三方授权与云端多租户 |

## 官方要求摘要

### 飞书

- 自建应用只面向一个企业，发布时由企业管理员审核；适合当前的内测模式。
- 商店应用面向多个租户，需要先完成 ISV 入驻，再经过应用创建、资料、方案、开发、测试和发布审核。
- 商店应用支持公开上架、不公开链接安装和定向灰度；定向发布有租户数量上限，适合小范围内测。
- 上架需要提交安全自查材料并接受平台安全审核。
- “用户进入与机器人的会话”事件可用于首次欢迎；官方要求开启机器人能力并订阅事件，客户端版本需满足平台要求。
- “机器人进群”事件可订阅，用于群聊首次欢迎；需要机器人能力和相应群信息权限。

### 企业微信

- 企业微信第三方应用通过服务商后台创建，企业管理员从工作台、应用市场或服务商渠道授权安装。
- 应用上线后可先通过自己的渠道推广；进入应用市场推荐位另有服务商资质、客户案例、研发/客服团队和方案评审要求。
- 智能机器人 API 长连接适合当前企业内测，不需要公网回调；第三方应用的多企业授权、代开发、回调与数据隔离不能由本机单实例替代。

### 钉钉

- 企业内部应用由本企业管理员创建和发布，机器人能力可使用 Stream 模式，不需要公网回调。
- 第三方企业应用需要先成为产品方案商/ISV，应用在应用市场上架前要经过平台审核，且通常有部署、安全和类目运营要求。
- 企业内部应用和第三方企业应用的授权模型不同；当前代码只覆盖前者，不能把“填写 Client ID/Secret”包装成第三方市场安装。

## 产品落地顺序

1. **现在：** 保持自建应用长连接，完成接入向导、错误诊断、首次欢迎和真实企业账号验收。
2. **小范围内测：** 飞书可使用商店应用的定向发布或安装链接；企业微信、钉钉先用服务商测试企业/测试组织。
3. **公开分发前：** 建云端多租户控制面，包含用户身份、租户授权、家庭映射、在线心跳、限流、审计、数据删除和客服流程。
4. **提审前：** 准备隐私政策、服务条款、数据流图、安全自查、客服与滥用处理、应用图标/截图/介绍和演示视频。
5. **公开发布：** 只让用户扫码或从应用市场安装；自建应用入口保留给企业和高级用户。

## 当前不建议做

- 不要承诺“任何普通用户填一个 Secret 就能接入飞书/企业微信/钉钉”。他们通常没有创建和发布企业应用的权限。
- 不要把本机 `127.0.0.1` 回调地址直接填到平台后台；Webhook 必须使用公网 HTTPS 域名，并映射到本机网关。
- 不要在未完成多租户隔离、限流、审计和删除机制前开放共享机器人注册。
- 不要把 QQ 个人号或个人微信协议接入作为正式方案；QQ 只能走官方机器人能力，当前仍未完成审核与沙箱联调。
