# 多账号与数据隔离

状态：已实现。单机可保存多个米家账号，并在账号之间切换；每个账号下的家庭、设备、摄像头、场景和自动化数据相互隔离。

## 用户流程

1. 首次登录：扫码后把账号加入本机账号库，并设为当前账号。
2. 添加账号：从账号浮层点击“添加米家账号”，再次扫码；旧账号数据不会在新账号登录过程中显示。
3. 切换账号：点击侧栏账号，选择另一个账号；界面先清空旧账号数据，再加载目标账号。
4. 退出当前账号：只移除当前账号。若仍有其他账号，自动切换到第一个剩余账号；若没有，显示登录页。
5. 单账号多家庭：账号不变时，顶部家庭选择器仍可切换该账号下的多个家庭。

## 存储

登录账号库：

```text
~/Library/Application Support/MiHome/accounts.json
```

账号库保存账号会话与显示名。文件权限为 `0600`，父目录权限为 `0700`。旧版 `session.json` 会在首次启动时自动迁移到 `accounts.json`，迁移成功后删除旧文件。

本地定时自动化按账号分文件保存：

```text
~/Library/Application Support/MiHome/automations/<sha256(user_id)>.json
```

文件名只使用 `userId` 的 SHA-256，不把原始账号 ID 放进路径。首次从旧版全局 `automations.json` 迁移时，任务归属当前活动账号，之后每个账号只读写自己的文件。

## 隔离边界

| 数据 | 隔离方式 |
| --- | --- |
| 登录会话 | 账号库中按 `user_id` 独立记录，活动账号单独标记 |
| 家庭与房间 | 切换账号后重新请求目标账号的家庭列表 |
| 设备与属性缓存 | 账号切换时清空前端设备、属性、传感器序列和检查器状态 |
| 摄像头 | 切换、退出和扫码登录前停止本地与远程取流并清空缓存 |
| 场景 | 始终使用当前 `home_id` 请求，旧账号响应因请求代次不匹配被丢弃 |
| 自动化 | 每个账号使用独立 JSON 文件，切换时替换整个存储实例 |
| 前端旧响应 | 账号代次、家庭 ID 和请求序号共同防护，旧请求不能回写新账号界面 |
| 登录轮询 | 取消添加账号或切换账号会使旧轮询代次失效，过期扫码结果不会写入账号库 |

规格缓存不按账号拆分。MIoT-Spec 是公开的设备能力数据，不包含家庭、设备凭据或个人状态，复用不会串账号数据。

## 安全边界

当前发行构建使用 ad-hoc 签名，凭据保存在仅当前 macOS 用户可读的私有文件中，不调用系统 Keychain，以避免升级二进制后反复触发钥匙串授权。该方案不能防御同一 macOS 用户下的恶意进程；正式 Developer ID 发行版应迁移到 Keychain 或等价保护。

日志与诊断包只记录脱敏账号/设备 ID、耗时、错误码和连接状态，不记录 `serviceToken`、`passToken`、`ssecurity`、Cookie 或完整媒体地址。
